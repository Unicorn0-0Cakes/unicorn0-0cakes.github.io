Multimodal Archaeological Site Detection

A three-tier detection pipeline, designed and scaffolded, with no dataset behind it and no result to report — which is the honest state of it and the reason it is here.

Research

Conceptual prototype
2026

Could a staged detector triage satellite, LiDAR and archival text faster than survey alone — and how would you know?

Read this first

This project has produced no detection, segmentation or classification results. No dataset has been acquired or processed end to end, no model has been trained on real data, and the training script currently runs on placeholder inputs with dummy declining loss values. Everything below describes an architecture and a set of design decisions. None of it describes a validated system.

01What it is

A proposed method for finding archaeological sites that nobody has recorded, by combining data sources that are each individually insufficient: multispectral satellite imagery, LiDAR-derived terrain products, and historical text. The proposal is a three-tier cascade, where each tier is cheap relative to the one after it and exists to reduce how much work the next tier has to do.

02Why

Archaeological prospection is bounded by survey time. The area that might contain something is enormous; the area anyone can walk is not. Any method that reliably narrows the search is valuable even if its precision is poor, provided its recall is good and its cost is low — which is a different optimisation target from the one most detection models are built for, and the reason a cascade is the interesting shape.

It is also a domain where a false positive and a false negative are not symmetrical errors, and where the consequences of publishing coordinates are not purely academic.

03My role

The architecture and its staging, the configuration system, the model cards, the preprocessing scaffolding for three different data modalities, the pipeline orchestration, and the documentation — including the decision to state the project's incompleteness in the first line of its README rather than at the bottom.

04The proposed pipeline

Tier 1 — Scan
A modified YOLOv8 detector sweeping wide areas of multispectral satellite imagery to flag points of interest quickly. Optimised for recall and throughput; precision is explicitly the next tier's problem.
Tier 2 — Delineate
SegFormer over high-resolution patches centred on the flagged points, to produce boundaries rather than points. Expensive per unit area, which is why it only ever sees what Tier 1 hands it.
Tier 3 — Characterise
A Swin Transformer over fused modalities — imagery, LiDAR derivatives, processed text — for classification and significance assessment. The tier where the multimodal claim actually lives, and the least specified of the three.

05Implemented and not implemented

Implemented

  • Three-stage pipeline structure and an orchestration script that sets out the intended call sequence
  • YAML configuration management, global and per-model
  • Draft architecture definitions for all three models
  • Preprocessing scaffolding for Sentinel imagery, LiDAR and text
  • Model cards in docs/ for each of the three components
  • MLflow experiment-tracking scaffolding

Not implemented

  • No dataset acquired, licensed or processed end to end
  • train.py uses placeholder data loading, a placeholder optimiser and dummy declining loss values
  • No checkpoint has been produced from real training
  • Evaluation is not connected to held-out data or ground truth
  • No detection, segmentation or classification metrics exist
  • Several features described in the model cards are explicitly hypothetical

06Outcome

What this project produced is a design and an honest account of its own state. That is a smaller claim than the repository could have made — the scaffolding is complete enough that it would have been easy to write about it in the present tense and let a reader assume the rest.

The more useful output was recognising why it stalled. The architecture was specified top-down, all three tiers at once, before a single tier had touched real data. Three model cards were written for models that had never been trained. The scope ran ahead of the evidence, and the correct response to that is not to build the fourth thing.

07Limitations

  • The three-tier cascade is a design proposal. It has not been validated as more effective or more efficient than a simpler baseline, and no such comparison has been run.
  • Data acquisition depends on external satellite, LiDAR and archival sources that are not integrated. GDAL and Rasterio are notoriously difficult to install and are not fully tested in this repository.
  • No ethical, legal or cultural-heritage review has been conducted. That review would be required before this pipeline ran against real archaeological data, not afterwards.
  • Archaeological site locations are sensitive information. Any future work on real data has to handle the risk of disclosing exact coordinates, which is a design constraint on the output format and not just an operational note.

08The next reproducible milestone

Narrow, rather than extend. One small, lawful, publicly available dataset — a satellite tile set with known reference sites. One real training loop, for Tier 1 only. One honest baseline to compare against, such as a classical thresholding detector. One evaluation with real precision and recall, reported plainly, including a null result if that is what comes out. Then write down what worked and what did not, before adding a second tier.

If that milestone produces a Tier 1 detector that cannot beat simple thresholding, the project has still answered its question. That outcome would be worth publishing here exactly as readily as the other one.
