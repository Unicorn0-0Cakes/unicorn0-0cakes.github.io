01 The standard

The hardest part of showing research on a portfolio is that a portfolio wants finished things and research mostly is not. The usual resolution is to describe an unbuilt system in the present tense and hope nobody opens the repository.

The resolution here is the opposite. Every research project separates what has been implemented from what has only been proposed, and the separation is the first thing you read — on the project page and in the repository's own README. Rigorous unfinished work is a legitimate thing to show. Unfinished work described as finished is not.

Implemented / proposed

Two columns, always. A reader should never have to open the source to find out which side something is on.

No unearned numbers

If a model has not been trained on real data, it has no metrics — and the page says that instead of leaving a gap for the reader to fill in optimistically.

A next milestone

Each project names the single smallest next step that would produce a real result. Usually it narrows the scope rather than widening it.
